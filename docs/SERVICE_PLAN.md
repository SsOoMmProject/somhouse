# 솜하우스 서비스 완성 순서

## 확정한 방향

프론트엔드는 GitHub Pages를 유지한다. 공유 기록과 AI 처리는 맥 미니에서 담당하며, 외부 연결은 Tailscale Funnel을 사용한다. 사용자는 휴대폰 브라우저만 사용한다. 서버 노출 작업보다 실제 사용 흐름을 먼저 완성한다.

## 1. 기기에서 실제 사용 흐름 완성

- 기존 수유·병원·일정·구매 기록 CRUD와 JSON 백업 유지
- 홈에서 빠른 기록, 오늘 수유 요약, 날짜·종류·검색어 및 구매 상태별 조회
- 실제 AI 미연결 상태 명시
- 오래 열린 다른 탭에서 기록을 저장하면 덮어쓰지 않도록 변경 감지

용량은 단위가 명시된 수유 기록만 합산한다. 합계나 간격으로 진단 또는 의학적 권고를 만들지 않는다. 브라우저 탭의 변경 감지는 일반적인 덮어쓰기를 줄이는 보호책이다. 두 탭이 정확히 동시에 저장하는 상황까지 원자적으로 처리하는 기능은 아니므로 한 탭 사용을 권장한다.

## 2. 공유·대화 서비스 구현

다음 구현은 공유 저장소와 인증, 단일 AI 대화 기능을 로컬 환경에서 함께 테스트한다. 서버 프로그램 개발은 서비스 기능의 일부이며, Funnel 공개 및 운영 설정과는 분리한다.

- 맥의 로컬 DB와 기록 API, 두 사용자 인증, 수정 충돌 감지
- 현재 브라우저 기록의 명시적 이전과 중복 방지
- 공유 기록 백업과 복원
- 단일 AI 대화: 실제 응답, 오류·대기 표시, 필요한 기록만 읽기
- AI가 기록을 변경할 때 사용자 확인

AI 공급자와 비용은 아직 미정이다. 로컬 테스트를 실제 부부 공유 또는 실제 AI 연결 성공이라고 보고하지 않는다. 서비스 API에는 로그인·기록 CRUD·백업·대화라는 경계를 두어 로컬 저장 방식과 서버 구현을 교체하기 쉽게 한다.

## 3. 운영 연결

서비스 기능이 테스트된 뒤 맥에 설치하고 자동 실행, 백업, Funnel HTTPS 연결을 적용한다. GitHub Pages에서 두 휴대폰을 통해 CORS, 인증 전달, 저장/조회, 연결 중단, AI 응답을 검증한다. CORS는 접근 권한을 대신하지 않는다. 개인 DB·비밀키·인증 토큰은 저장소에 넣지 않는다. 실제 외부 접근 성공 전까지 서비스 전체를 완성됐다고 보고하지 않는다.
