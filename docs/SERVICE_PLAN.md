# 솜하우스 서비스 완성 순서

## 확정한 방향

프론트엔드는 GitHub Pages를 유지한다. 공유 기록과 AI 처리는 맥미니에서 담당하며, 외부 연결은 Tailscale Funnel을 사용한다. 사용자는 휴대폰 브라우저만 사용한다. 서버 운영 설정보다 실제 사용 흐름을 먼저 완성한다. Firebase는 이 구성에 사용하지 않는다.

2026-11-02 사용자 요청: **동시 수정 충돌 처리는 가장 마지막으로 미룬다.** 같은 항목은 마지막 저장을 적용한다. 기록 API는 항목 단위로 저장하여 서로 다른 기록을 추가할 때 전체 목록을 덮어쓰지 않는다.

## 1. 기기 기록 — 구현됨

- 수유·병원·일정·구매 기록 CRUD와 JSON 백업
- 홈의 빠른 기록, 오늘 수유 요약, 날짜·종류·검색·구매 상태 조회
- 기존 somhouse-v1 형식과 저장 오류·다른 탭 변경 보호 유지
- 실제 AI 미연결 상태 명시

## 2. 로그인과 맥미니 공유 저장 — 구현, 로컬 API 검증

- 가족 계정 두 개, 비밀번호 해시, 만료·로그아웃 가능한 로그인
- SQLite 기록 API, 항목별 저장·삭제, 같은 가족 데이터 조회
- 공유 기록과 브라우저 원본 저장소 분리
- 기기 기록의 명시적 이전: 원본 JSON 다운로드, 중복 건너뛰기, ID 충돌 시 양쪽 보존
- JSON 가져오기로 현재 기록을 지우지 않는 백업 복원
- 변경 전 공유 기록 자동 백업, 연결 실패 시 입력과 기존 화면 유지
- 10초 간격 및 화면 복귀 시 공유 목록 조회 (편집창을 열었을 때는 자동 조회 보류)

인증 토큰은 브라우저 sessionStorage에 저장한다. 새 탭이나 앱 종료 후에는 다시 로그인이 필요할 수 있다. 서버·계정·백업 운영법은 README를 참조한다.

자동 검증은 임시 DB를 사용한다. 실제 Safari 화면·실제 두 휴대폰의 공유 성공은 아직 확인하지 않았다. Work의 브라우저 자동 제어는 비활성화되어 있었고, Safari 네이티브 접근도 시간 초과로 실패했다.

## 3. HTTPS와 실제 두 휴대폰 검증 — 연결 작업 중

- GitHub Pages에 로그인 화면과 공개 API 주소 설정 배포
- 맥 사용자 로그인 시 API 자동 실행 설치 완료
- Tailscale Funnel은 계정에서 비활성화되어 소유자의 웹 활성화 승인 대기
- CORS, 로그인 전달, 두 휴대폰의 추가·조회·수정·삭제·백업·연결 중단 확인
- Funnel 활성화 후 HTTPS·CORS·실제 두 휴대폰 검증, 백업 운영 확인

실제 외부 접근 성공 전까지 두 휴대폰 공유를 완성했다고 보고하지 않는다. DB·초기 비밀번호·토큰은 저장소에 넣지 않는다.

## 4. 단일 AI 연결

- 공급자·모델·비용 결정 후 서버에서만 API 키 관리
- 실제 응답과 오류·대기 표시, 필요한 기록만 읽기
- AI가 기록을 변경할 때 사용자 확인
