# 내 AI 앱 커넥터 (MCP) 설계 · 2026-11-21 기준

**상태: 설계만 있다.** 가족의 ChatGPT·Claude·Gemini 앱이 솜하우스 기록을 직접 읽게 하는 방식이다. 운영자가 AI 비용을 내지 않고, 키 없이 구독을 그대로 쓴다는 점이 가장 큰 장점이다.

## 왜 지금 구현하지 않는가

이 기능은 **아기 건강 기록을 읽는 공개 인터넷 주소**를 하나 더 여는 일이다. 인증을 제대로 구현하려면 OAuth 2.1 인가 서버가 필요하고, 맥미니 + Funnel 구조에서는 사고가 나면 모든 가족의 기록이 걸린다. 비밀 주소만으로 막는 방식은 건강 기록에 쓰지 않는다.

그동안의 수요는 **내 AI 앱으로 보내기 PR**이 대부분 해결한다. 그쪽은 숫자를 사람이 직접 보내고, 서버를 열지 않는다.

| | 내 AI 앱으로 보내기 | MCP 커넥터 |
|---|---|---|
| 필요한 것 | 없음 | 인가 서버, 보안 점검 |
| AI가 보는 것 | 사람이 보낸 그 글 | 도구 범위 안의 기록 |
| 후속 질문 | 다시 보내야 함 | AI가 알아서 조회 |
| 사고 범위 | 한 번 보낸 글 | 연결된 가족 기록 |

## 열리는 조건

- [ ] 동의·내 데이터 센터 적용 (AI 전송 동의를 커넥터에도 적용)
- [ ] 서버가 맥미니 + Funnel을 벗어나거나, 가족별로 분리된 구조로 전환
- [ ] 외부 보안 점검 또는 그에 준하는 검토
- [ ] 실제 가족이 “보내기”로는 부족하다고 느낀다는 사용 근거

## 설계

**도구는 읽기 전용, 집계부터.** 쓰기 도구는 첫 버전에 넣지 않는다.

| 도구 | 돌려주는 것 | 넣지 않는 것 |
|---|---|---|
| `get_summary(from, to)` | 날짜별 수유·수면·기저귀 집계 | 메모, 병원 이름, 아기 이름 |
| `get_last_events()` | 마지막 수유·수면·기저귀 시각 | 입력자 |
| `query_records(metric, from, to, part)` | 기록에 물어보기 PR과 같은 계산 결과 | 개별 기록 원문 |
| `get_upcoming()` | 7일 일정 건수와 시각 | 일정 제목은 사용자가 켠 경우만 |

**인증과 통제**

- OAuth 2.1 + PKCE, 리소스 표시자로 토큰을 이 서버 전용으로 제한
- 토큰은 가족 단위 + 사람 단위, 범위는 `read:summary`만, 해시로 저장, 만료 1시간
- ‘가족 관리’에서 연결된 AI 앱을 보고 즉시 끊기
- 호출 기록(언제, 어떤 도구)을 가족이 볼 수 있게 남긴다. 응답 내용은 남기지 않는다
- 사람당 호출 한도, 조회 기간 최대 90일
- 도구 응답은 데이터로만 다룬다. 기록의 메모에 적힌 문장이 AI에게 지시처럼 전달되지 않도록 원문을 내보내지 않는다

## 지원 범위 (변동이 잦아 구현 시점에 다시 확인)

- Claude: 원격 MCP 커스텀 커넥터를 Free(1개)·Pro·Max·Team·Enterprise에서 지원 ([공식 안내](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp))
- ChatGPT: 개발자 모드에서 커스텀 커넥터 지원, 대상 요금제는 자료마다 달라 확인 필요
- Gemini 앱: 이번 조사에서 공식 자료를 확인하지 못했다
