# 앱 전환 설계 — 각 가족의 Google 계정이 서버 역할 (보관용 · 2026-11-18)

**상태: 서버 방향으로 선택(2026-11-20, 순수 비용이 가장 낮아서). 구현 착수 전, 웹 버전 개선을 계속한다.** 이전 상태: 미래 계획. 지금은 UI·UX와 기능 개선에 집중하고, 이 문서는 Draft PR로만 보관한다. 현재 맥미니 버전은 우리 가족용으로 계속 운영한다.

## 목표

웹을 다른 가족도 쓰는 앱으로 만든다. 맥미니 + Tailscale Funnel은 공개 사용자를 감당할 수 없고(2026-11-18 공개 중계 연결 설정 평균 5.7초·최대 19초 측정), 중앙 서버를 운영하면 다른 가족의 Google 권한과 아기 건강 기록을 우리가 보관하게 된다. 그래서 **각 가족의 Google 계정이 저장소·동기화·입력 경로를 맡고, 계산은 휴대폰이 한다.**

## 선택지

| 방식 | 구조 | 판단 |
|---|---|---|
| **A. 앱 + 각 가족 Drive의 Google 시트 (채택 후보)** | 앱이 휴대폰에서 Google 로그인, 가족 Drive의 시트를 저장소로 사용 | 서버 비용 0, 데이터는 각 가족 계정에만 존재 |
| B. 가족별 Apps Script | 각 계정에 스크립트 설치, 1~5분 트리거 | 상시 처리는 좋지만 일반 사용자 배포·업데이트가 어렵고 무료 실행 한도(소비자 계정 트리거 일 90분)가 빠듯함 |
| C. 중앙 클라우드 서버 | Cloud Run 등 직접 운영 | 비용, 남의 토큰·건강 기록 보관 책임 — 목표와 반대 |

## A안 설계

### 저장소
- 첫 로그인 때 앱이 가족 Drive에 시트를 만든다. `drive.file`(앱이 만든 파일만 접근, 비민감 권한).
- **추가만 하는 이벤트 로그**(현재 "원본 기록" 탭과 같은 형태). 각 기기가 로그를 읽어 현재 상태를 계산하고, 같은 항목 충돌은 나중 저장 우선(현재 규칙과 동일).
- 부부는 같은 계정을 쓰거나 시트를 공유한다. 가족 구분 규칙은 아래 "가족 구분" 참조.
- 기기에 로컬 사본(IndexedDB 또는 SQLite) → 오프라인 표시, 앱이 열려 있을 때 약 10초 간격 동기화. Sheets 사용자당 분당 60회 읽기 한도 안.

### 가족 구분 (같은 가족 = 같은 기록, 2026-11-20 추가)

맥 버전(PR `feature/families`)과 사용자에게 보이는 규칙을 같게 한다. 다만 앱에는 중앙 명단이 없으므로 **가족 = 같은 솜하우스 시트에 접근 권한이 있는 Google 계정들**로 정의하고, 데이터 분리는 Google Drive 권한이 보장한다.

| 맥 버전 | 앱 |
|---|---|
| 처음 보는 계정 → 빈 새 가족 | 접근 가능한 솜하우스 시트가 없으면 → 새 시트를 만들어 새 가족 |
| 이메일 미리 등록 | 앱이 Drive API `permissions.create`로 그 주소에 시트 **편집자** 권한 부여(`drive.file`은 앱이 만든 파일의 공유 변경 가능) |
| 7일 초대 링크(누구나 사용) | **이메일 공유 + 링크.** 모르는 계정에 링크만으로 열어 주려면 "링크가 있는 모든 사용자" 공유가 필요해 아기 건강 기록에는 쓰지 않는다. 링크(`#join=<시트 ID>`)는 공유받은 사람이 시트를 찾기 쉽게 하는 용도이고, 실제 출입은 공유 목록이 정한다. |
| 내보내기 / 나가기 | `permissions.delete`(내보내기), 자기 권한 삭제 + 기기 사본 삭제(나가기) |
| 기록이 있는 가족의 마지막 구성원은 나갈 수 없음 | 같음. 시트 소유자는 나가기 대신 소유권 이전 또는 시트 삭제 안내 |

- **`drive.file` 제약:** 공유받은 시트도 그 사람의 앱이 "연 적이 있는" 파일이어야 읽을 수 있다. 그래서 공유받은 사람은 처음 한 번 **Google Picker**로 그 시트를 선택한다(`setFileIds`로 해당 시트만 보이게). 초대 링크와 공유 알림 메일이 이 단계로 바로 안내한다. 더 넓은 Drive 권한은 요청하지 않는다.
- **계정당 가족 하나:** 앱은 마지막으로 연 시트를 기억한다. 접근 가능한 솜하우스 시트가 여럿이면 고르는 화면을 보여 준다.
- **음성 입력:** 각 구성원의 Nest·Gemini 입력은 그 사람 계정의 캘린더·Tasks에 생긴다. 앱에서는 **각자의 휴대폰이 자기 계정의 입력을 읽어 공유 시트에 이벤트로 추가**하므로, 계정이 나뉜 가족도 중앙 서버나 캘린더 공유 없이 음성 입력을 쓸 수 있다(맥 버전의 열린 문제가 앱에서는 사라짐).
- **맥 버전에서 옮기기:** 맥의 `families/<id>`(새 가족)와 기본 가족 데이터는 각 가족 시트로 이벤트 로그 형태로 내보내 옮긴다. 미리 등록한 주소는 시트 공유로 바꾼다.

### 음성·캘린더 입력 (2026-11-20 결정 반영)
- Nest 음성은 지금처럼 그 계정의 캘린더·Tasks에 남는다(유실 없음). 음성 입력은 자주 쓰지 않으므로 처리 지연을 허용한다.
- **자동 + 수동 동기화:** 앱을 열 때·화면에 돌아올 때 자동, 앱이 열려 있는 동안 1~2분 간격, 홈의 ‘마지막 수유’ 근처에 **‘음성 입력 가져오기’ 버튼**과 마지막 확인 시각. Android 앱 단계에서 백그라운드 작업(WorkManager, 최소 약 15분, 보장 안 됨)을 더할 수 있다.
- **웹(PWA) 단계의 제약:** 서버가 없어 Google 갱신 토큰을 둘 곳이 없다. 접근 토큰은 약 1시간이고 만료 뒤 새 토큰은 사용자 탭(팝업)이 필요하다. 그래서 앱을 열 때 자동 동기화는 토큰이 살아 있을 때만 하고, 아니면 수동 버튼이 토큰 갱신 겸 동기화를 맡는다. Android 네이티브 단계에서 완전 자동(백그라운드 토큰 발급은 구현 때 확인).
- **중복 방지:** 같은 계정을 여러 휴대폰이 동시에 처리해도 Calendar 일정 ID·Task ID를 기록 키로 써서 한 번만 반영한다(현재 맥 버전과 같은 방식). Calendar는 증분 동기화 토큰, Tasks는 updatedMin으로 바뀐 것만 읽는다.
- 음성 기록의 시각은 처리 시각이 아니라 일정 시작 시각(직접 입력 규칙 포함)을 쓴다. 늦게 가져와도 수유 시각·수면 자동 종료가 틀어지지 않는다.

### 수유 캘린더는 휴대폰 캘린더에 직접 기록 (2026-11-20)
- 맥 버전 시험에서 확인: 서버가 Google 캘린더에서 일정을 지운 뒤(즉시 반영, Google 웹에서 바로 사라짐) **삼성 캘린더에는 약 35분 뒤에야** 반영됐다. 휴대폰 캘린더 앱이 Google에서 언제 받아 올지는 휴대폰이 정하므로 웹·서버 쪽에서는 앞당길 수 없다.
- **Android 앱에서는 수유 캘린더 일정을 휴대폰의 캘린더 저장소(CalendarContract)에 직접 넣고 고치고 지운다.** 그 Google 계정의 ‘솜하우스 수유’ 캘린더에 쓰면 기록하는 순간 위젯·캘린더 앱에 보이고, Google로는 휴대폰의 동기화가 나중에 올린다. Google Calendar API로 직접 쓰는 방식과 섞으면 같은 일정이 두 번 생길 수 있으므로 한 가지 경로(휴대폰 캘린더 저장소)로만 쓴다.
- 필요한 것: Android 캘린더 읽기·쓰기 권한(READ/WRITE_CALENDAR), 그 계정의 ‘솜하우스 수유’ 캘린더 찾기·만들기, 기록 ID ↔ 휴대폰 일정 ID 연결(기기별). 다른 가족 구성원의 휴대폰에는 Google 동기화로 전달된다(그쪽은 지연 가능).
- PWA 단계에서는 이 방법을 쓸 수 없으므로 지금처럼 Google Calendar API로 쓰고, 솜하우스 화면을 기록 확인의 기준으로 안내한다.

### 앱 형태
- 현재 웹 코드를 살려 **Capacitor로 Android 앱**, 같은 코드로 PWA 유지.
- 휴대폰 내 Google 로그인(서버 비밀값 불필요).

### 공개 출시 조건
- Calendar·Tasks는 **민감 권한** → Google OAuth 앱 검토(개인정보처리방침, 홈페이지, 시연 영상, 보통 수 주). 제한 권한이 아니므로 CASA 보안 감사는 대상 아님.
- **개인 도메인** 필요(github.io·ts.net은 소유 확인 불가). 정책·소개 페이지를 그 도메인에.
- 검토 통과 후 Testing 앱의 7일 refresh token 만료가 사라짐.
- Play 스토어 개발자 등록비 25달러.

### 빠지거나 바뀌는 기능
- AI 대화(맥의 Antigravity CLI): 제외 또는 Gemini API 연동으로 교체.
- 가격 검색(SerpApi 키): 제외 또는 사용자 제공 키 선택 기능.
- 맥 자동 백업 → 시트 버전 기록 + 앱 내 내보내기.

## 진행 순서 (재개 시)
1. 현재 맥 버전 계속 운영.
2. 핵심 로직을 JavaScript로 이식: 음성·캘린더 제목 해석(`calendar_records`, `google_records.voice_payload`), 수면 자동 종료(`sleep_wake`), 확인 필요 처리. 화면 계산(`service.js`)은 이미 JS.
3. 웹에 **"맥 없이 Google 시트에 저장" 시험 모드**를 추가해 우리 가족 계정으로 먼저 사용(저장소 선택: 맥 / Google 시트).
4. Capacitor Android 앱 + 백그라운드 입력 처리.
5. 도메인 → 개인정보처리방침 → Google 검토 → Play 스토어.

## 열린 질문
- Nest 음성이 Tasks와 캘린더 중 어디로 가는지 기기별 확인(기기 테스트 할 일과 겹침).
- 시트 이벤트 로그가 수만 행이 될 때 초기 로딩 시간 — 월별 탭 분리 또는 스냅샷 행 필요 여부.
- ~~가족 간 공유 시 계정이 분리된 경우의 음성 입력~~ → 앱에서는 각 구성원의 휴대폰이 자기 입력을 처리(위 "가족 구분"). 맥 버전용 공유 캘린더 방안은 할 일 목록에 보관.
- 시트 소유자가 계정을 지우거나 공유를 끊을 때 다른 구성원의 기기 사본을 어떻게 안내할지.
