# 솜하우스

가족의 육아 기록, 일정, 구매 목록을 관리하는 모바일 중심 웹앱입니다. 서버 없이 사용하는 기기 저장 모드와, 로그인 후 맥미니에 함께 저장하는 가족 공유 모드를 제공합니다. 가족 로그인 화면을 GitHub Pages에 배포합니다. Tailscale Funnel HTTPS 연결을 완료했으며, 실제 두 휴대폰의 기록 공유 확인과 AI 연결은 남아 있습니다.

## 실행

`index.html`을 브라우저에서 열거나 이 폴더에서 `python3 -m http.server 8000`을 실행한 뒤 http://localhost:8000/ 에 접속하세요. 설치나 빌드가 필요 없습니다. HTML, CSS, 순수 JavaScript를 선택해 GitHub Pages의 하위 경로에서도 별도 설정이나 빌드 없이 작동합니다. 화면은 한 페이지에서 바뀌므로 새로고침과 직접 접속 시 서버 측 라우팅이 필요하지 않습니다.

## 저장과 백업

기기 저장 모드의 데이터는 이 기기의 해당 브라우저 localStorage에만 저장됩니다. 배우자나 다른 기기에 자동 공유되지 않으며 브라우저 데이터를 삭제하면 사라질 수 있습니다. JSON 내보내기로 정기적으로 백업하세요. 가져오기는 확인 후 현재 브라우저의 모든 기록을 덮어씁니다. 백업 파일에는 개인 기록이 포함될 수 있으니 안전하게 보관하세요. 예시 개인 데이터는 포함하지 않습니다.

## 배포

GitHub 저장소에 파일을 올린 뒤 Settings → Pages → Build and deployment에서 브랜치 배포를 선택하고 기본 브랜치의 `/ (root)`를 선택합니다. 발급된 주소에서 접속을 확인하세요. GitHub Pages 사이트는 외부에 공개될 수 있으며 저장소의 소스코드 공개 범위는 별도 설정입니다. 비공개 저장소의 Pages 사용 가능 여부는 계정 요금제와 설정에 따라 다릅니다. 개인 기록이나 비밀 키를 저장소에 올리지 마세요.

## 나중에 연결할 기능

AI 화면은 연결되지 않은 상태입니다. 로그인·공유 저장 다음에 Tailscale Funnel HTTPS를 연결하고, 이후 단일 AI를 맥미니 서버에서 연결합니다. AI 공급자·모델·비용은 아직 미정이며 비밀 키는 서버에서 관리합니다. Google Keep, Calendar, Nest, 쇼핑몰 및 기존 SsOoMm AI 연결은 향후 검토 사항입니다.

## 저장 오류와 복구

저장된 데이터를 읽거나 해석할 수 없으면 앱은 저장을 잠그고 기존 값을 덮어쓰지 않습니다. 화면에 표시되는 빈 목록은 실제 기록이 아닙니다. 브라우저의 저장 공간과 사이트 데이터 접근 설정을 확인한 뒤 새로고침하세요. 문제가 계속되면 브라우저 데이터를 지우지 말고, 개발자 도구의 해당 사이트 localStorage에서 `somhouse-v1` 원본 값을 안전한 곳에 복사해 보관한 다음 복구에 도움을 받으세요. 원본에는 개인 기록이 있을 수 있으니 공개하지 마세요. 정상 백업을 복원하려면 원본을 안전하게 보관하고 백업 파일이 있는지 확인하세요. 데이터 손상으로 잠긴 경우 개발자 도구에서 이 사이트의 `somhouse-v1` 항목만 제거하고 새로고침한 다음 JSON 가져오기를 사용하세요. 접근 설정 문제라면 설정을 해결한 뒤 새로고침하세요.

변경 사항을 저장하지 못하면 화면의 기존 목록도 유지됩니다. 오류를 해결한 후 다시 시도하세요. JSON 가져오기는 필수 항목과 자료형을 검사하며, 유효한 파일만 덮어쓰기 확인 후 저장합니다.


## 서비스 사용성 보완

`service.js`의 날짜별 요약과 필터를 사용합니다. 홈의 빠른 기록, 오늘 수유 횟수와 명시된 용량 합계, 최근 수유, 날짜·유형·검색어·구매 상태별 검색을 제공합니다. 새 기록의 시간은 기기의 현재 시각으로 채웁니다. `#records` 등 메뉴 경로를 새로고침해도 같은 메뉴로 열립니다.

기존 `somhouse-v1` 데이터와 JSON 형식을 유지합니다. 다른 탭이 기록을 변경하면 오래된 탭에서 저장을 막고 새로고침을 안내합니다. 동시 저장의 완전한 충돌 방지는 서버 단계에서 구현합니다. 요약은 자정 이후 또는 시간 경과 후 화면을 다시 열거나 새로고침하면 갱신됩니다.

검증: `node --test tests/service.test.cjs`. 실제 Chrome 미리보기에서 가상 수유 추가 → 홈 요약 반영, 검색 결과 없음, 새로고침 후 기록과 메뉴 유지 확인. 이번 수정에 대해 Safari와 실제 휴대폰 시험은 아직 수행하지 않았습니다. 브라우저 저장 실패·다중 탭 충돌은 VM 모의 저장소로 확인합니다.

서비스 우선 개발 순서와 연결 확정 사항은 [SERVICE_PLAN.md](docs/SERVICE_PLAN.md)를 참조하세요. 맥미니 로그인·공유 API와 자동 실행을 구현했습니다. Funnel HTTPS와 두 계정의 원격 API 검증을 완료했으며, 실제 AI와 실제 두 휴대폰 검증은 아직 완료하지 않았습니다.

## 가족 로그인과 맥미니 공유 저장

로그인하지 않은 상태는 기존 기기 저장 모드입니다. `가족 공유 설정`에서 서버 주소와 가족 계정으로 로그인하면 맥미니의 같은 기록을 사용합니다. 공유 모드의 기록은 `somhouse-v1`에 쓰지 않으므로 기기 원본이 남습니다. 로그아웃하면 이 브라우저의 기기 기록으로 돌아갑니다.

### 맥미니에서 시작

Python 3.10 이상이면 추가 패키지 없이 실행합니다. 기본 저장 위치는 저장소 밖의 `~/Library/Application Support/Somhouse/`입니다.

```sh
python3 server.py init
python3 server.py serve
```

`init`은 `family1`, `family2` 계정과 임의의 비밀번호를 생성합니다. 초기 로그인 정보는 위 폴더의 `initial-accounts.txt`에서 확인하세요. 이 파일과 DB 폴더는 소유자 전용 권한으로 생성되며 웹 서버가 제공하지 않습니다. 다시 `init`을 실행해도 기존 계정과 기록을 초기화하지 않습니다.

맥에서 http://127.0.0.1:8787/ 에 접속하고, 가족 공유 설정의 서버 주소도 `http://127.0.0.1:8787`로 지정하세요. 서버는 루프백에만 바인딩합니다. 휴대폰에서 이 주소를 입력하면 휴대폰 자신을 가리킵니다. GitHub Pages에서는 config.js에 지정한 Funnel HTTPS 주소를 자동으로 사용합니다. 현재 계정에서 Funnel 활성화 승인을 완료했습니다. **HTTPS 연결은 검증했으며, 실제 두 휴대폰의 기록 공유 시험은 아직 필요합니다.**

비밀번호를 직접 바꾸려면 다음 명령으로 터미널에서 새 값을 입력하세요. 해당 계정의 기존 세션은 해제됩니다. 초기 로그인 정보 파일은 자동 갱신하지 않습니다.

```sh
python3 server.py password family1
```

시험용 DB는 `--data-dir /private/tmp/솜하우스시험폴더`, 포트는 `--port 8788`처럼 별도로 지정할 수 있습니다. 실제 계정과 기록이 있는 폴더로 테스트하지 마세요.

### 기존 기록 이전과 복원

1. 기존 기록을 저장한 **그 휴대폰의 같은 브라우저·같은 사이트**에서 가족 공유에 로그인합니다.
2. `이 기기 원본 N개를 공유에 병합`를 누르면 확인 후 원본 JSON을 내려받고 공유 저장소에 병합합니다. 브라우저 원본은 삭제하지 않습니다. 내려받은 파일도 보관하세요. 기기 원본이 없으면 이전 버튼은 숨깁니다. 로그인 후 입력한 기록은 이미 공유 저장되므로 별도 이전이 필요 없습니다.
3. 다른 휴대폰에서도 같은 과정을 실행합니다. 같은 내용은 건너뛰고, 같은 ID에 다른 내용이 있으면 별도 ID로 양쪽을 보존합니다. 이전 완료 후 수정·삭제한 기록은 같은 원본을 반복 이전해도 되살리지 않습니다.
4. 사이트·브라우저를 바꿨다면 원래 브라우저에서 JSON을 내보낸 뒤 공유 모드에서 JSON 가져오기를 사용합니다.

공유 모드의 `JSON 내보내기`는 서버의 최신 기록을 조회한 뒤 백업합니다. `JSON 가져오기`는 백업 복원용 병합입니다. 현재 기록을 지우지 않으며 삭제했던 기록도 복구할 수 있습니다. 백업과 현재 기록의 내용이 다르면 두 버전이 남을 수 있습니다. 기기 모드의 JSON 가져오기는 기존처럼 확인 후 기기 기록을 덮어씁니다.

서버는 매 변경 전에 `backups/`에 공유 기록 JSON을 저장하며, 백업 생성에 실패하면 변경을 적용하지 않습니다. 이 백업은 앱의 공유 모드에서 JSON 가져오기로 복원할 수 있습니다. `somhouse.sqlite3`는 계정과 세션도 포함합니다. 운영 중 DB를 복사해야 한다면 SQLite 백업 API를 사용하거나 서버를 종료하고 DB와 WAL 관련 파일을 함께 안전하게 보관하세요.

### 현재 동작과 한계

- 서로 다른 기록은 항목별로 저장합니다. 같은 기록의 수정은 마지막 저장을 적용하며 동시 수정 충돌 안내는 가장 마지막 단계로 미뤘습니다.
- 공유 목록은 10초 간격, 화면 복귀, 수동 새로고침 때 조회합니다. 편집 중 자동 조회는 보류합니다.
- 연결에 실패하면 공유 기록을 기기 저장으로 바꾸지 않습니다. 입력창을 유지하고 실패를 표시합니다. 실패 후 다시 저장할 때 같은 ID를 사용합니다.
- 로그인은 [sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)의 Bearer 토큰을 사용하고, 서버에서 30일 후 만료됩니다. 탭 종료 후에는 재로그인이 필요할 수 있습니다. 타 사이트 쿠키에 의존하지 않습니다.
- 기본 [CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) 허용 출처는 GitHub Pages와 로컬 개발 주소입니다. 별도 출처는 `--origin https://주소`로 명시합니다. 출처 허용과 별개로 기록 API는 로그인을 검사합니다.
- 서버는 지정한 프론트 파일만 제공합니다. 저장소 폴더 전체를 이 서버의 정적 경로로 공개하지 않습니다.

### 검증

```sh
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

JavaScript 테스트는 기기 기록 보존·연결 실패·로그인 만료를, 실제 HTTP API 테스트는 임시 DB로 두 계정 공유·백업·이전·복원·인증·CORS를 검증합니다. 이번 로그인·공유 변경의 실제 Safari 화면과 두 휴대폰 검증은 미수행입니다. 브라우저 제어 비활성화 및 네이티브 Safari 접근 시간 초과로 자동 UI 검증을 완료하지 못했습니다.

### 자동 실행과 HTTPS 연결

이 체크아웃을 맥 사용자 로그인 시 자동 실행하려면 `python3 scripts/install_service.py`를 실행합니다. LaunchAgent `com.ssoomm.somhouse`는 종료된 서버를 다시 실행하고, 로그는 전용 데이터 폴더에 저장합니다. 맥 전원과 사용자 로그인·네트워크가 유지되어야 합니다.

외부 HTTPS 프록시는 다음 명령으로 이 API 포트만 연결합니다.

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale funnel --bg 8787
```

현재 계정의 Funnel 활성화 승인은 완료했습니다. 새 환경에서 Funnel이 비활성화되어 있다면 최초 승인이 필요합니다. CLI가 출력한 Tailscale 승인 페이지를 계정 소유자가 열어 승인해야 합니다. 승인 뒤 명령을 다시 실행하고, HTTPS `/api/health`와 Pages 출처의 CORS·가족 로그인을 검증하세요. 정책·도메인은 [Tailscale 공식 안내](https://tailscale.com/docs/features/tailscale-funnel)를 참조합니다.

공개 API 주소는 `config.js`에만 두며 비밀번호나 토큰을 넣지 않습니다. 로그인 입력칸은 첫 화면에 표시하고 서버 주소는 설정 안에 미리 채웁니다. 기존 기기 기록을 보존하려면 원래 사용하던 GitHub Pages 주소와 브라우저에서 이전 기능을 실행하세요.
