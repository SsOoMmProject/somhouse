# 솜하우스

가족의 육아 기록, 일정, 구매 목록을 함께 관리하는 모바일 웹앱입니다. GitHub Pages의 같은 주소에서 가족 계정으로 로그인합니다. 추가·수정·삭제는 맥미니 SQLite에 저장하고, 다른 휴대폰에도 자동으로 반영합니다.

## 사용 흐름

- 로그인 후 모든 기록은 같은 가족 저장소를 사용합니다. 별도 공유·이전·새로고침 버튼은 없습니다.
- 사용자가 저장하거나 삭제하면 서버에 바로 반영합니다. 다른 휴대폰은 화면이 보일 때 2초 간격으로 변경을 확인합니다. 화면 복귀·네트워크 복구 때도 다시 조회합니다.
- 입력창·검색 조건을 작성 중이면 자동 화면 갱신을 보류해 입력을 유지합니다. 편집창을 닫으면 바로 다시 조회합니다. 변경이 없으면 목록을 다시 만들지 않습니다.
- 연결 실패 시 입력과 기존 목록을 유지하고 실패를 표시합니다. 저장되지 않은 내용을 저장 완료로 표시하지 않으며 기기 전용 저장으로 전환하지 않습니다.
- 로그인하지 않은 상태에서는 기록을 추가·수정·삭제할 수 없습니다.
- JSON 내보내기·가져오기, 기기 원본 백업·이전, 서버 주소 설정은 사용자 화면에 제공하지 않습니다. 백업·복원은 관리자가 맥에서 수행합니다.

홈의 빠른 기록·오늘 수유 요약, 육아 기록·일정·구매 목록의 검색과 필터를 제공합니다. 수유 용량은 단위가 명시된 기록만 합산합니다. Antigravity CLI를 연결하면 로그인한 가족이 **AI 대화** 탭에서 질문할 수 있습니다.

## 기존 기록 보존

기존 브라우저 localStorage의 `somhouse-v1` 원본은 읽기만 하며 덮어쓰거나 지우지 않습니다. 같은 사이트·브라우저에서 로그인하면 예전 기록을 자동으로 병합합니다. 같은 내용은 건너뛰고 ID가 같은 다른 내용은 별도 ID로 양쪽을 보존합니다. 이미 이전한 후 수정·삭제한 기록은 같은 원본을 다시 확인해도 되살리지 않습니다.

원본이 손상되었거나 브라우저 접근이 막혔으면 원본을 그대로 보존하고 안내합니다. 현재 가족 기록은 계속 사용할 수 있습니다. 이미 내려받은 JSON은 관리자 복원에 사용할 수 있습니다. 다른 사이트나 브라우저의 원본을 자동으로 읽을 수는 없습니다.

## 맥미니 실행

Python 3.10 이상이면 추가 패키지 없이 실행합니다.

```sh
python3 server.py init
python3 server.py serve
```

기본 전용 폴더는 `~/Library/Application Support/Somhouse/`이며 저장소 밖에 있습니다. `init`은 `family1`, `family2`와 임의의 초기 비밀번호를 생성합니다. 로그인 정보는 이 폴더의 `initial-accounts.txt`에만 저장합니다. 이미 계정이 있으면 계정이나 기록을 초기화하지 않습니다.

서버는 `http://127.0.0.1:8787/`에만 바인딩합니다. 휴대폰 프론트는 `config.js`의 HTTPS API 주소로 연결합니다. 이 파일에는 공개 주소만 두고 비밀번호·토큰·API 키는 넣지 않습니다.

```sh
python3 scripts/install_service.py
```

LaunchAgent `com.ssoomm.somhouse`는 맥 사용자 로그인 시 서버를 시작하고 종료되면 다시 실행합니다. 로그는 전용 폴더의 `service.log`, `service-error.log`에 저장합니다. 맥의 전원·사용자 로그인·네트워크가 유지되어야 합니다.

가족 계정으로 로그인한 뒤 상단의 **비밀번호 변경**에서 현재 비밀번호와 새 비밀번호를 입력하세요. 기억하기 쉬운 12~256자의 문구를 사용할 수 있습니다. 변경한 브라우저는 로그인 상태를 유지하고, 같은 계정의 다른 세션은 해제합니다.

현재 비밀번호를 잊었다면 관리자가 맥 터미널에서 재설정할 수 있습니다. 해당 계정의 모든 세션은 해제됩니다. 초기 로그인 정보 파일에는 처음 생성한 비밀번호만 남습니다.

```sh
python3 server.py password family1
```

## 관리자 백업·복원

서버는 기록 변경 전에 전용 폴더의 `backups/`에 JSON을 자동 보관합니다. 백업 생성에 실패하면 기록을 변경하지 않습니다. 백업 파일은 웹으로 제공하지 않습니다.

수동 백업:

```sh
python3 server.py backup
```

관리자 복원:

```sh
python3 server.py restore --file /안전한경로/backup.json
```

복원은 파일 전체를 검증하고 현재 상태를 먼저 백업한 뒤 병합합니다. 현재 기록은 삭제하지 않으며 같은 내용은 건너뜁니다. 삭제했던 기록을 복구할 수 있고, 현재와 다른 버전은 별도 기록으로 남을 수 있습니다. 가족 계정으로 호출하는 웹 복원 API는 제공하지 않습니다. 복원 작업은 다른 기록 변경이 없는 점검 시간에 수행하세요.

`somhouse.sqlite3`는 계정과 세션도 포함합니다. DB 전체 백업은 SQLite 백업 API를 사용하거나 서버를 종료하고 DB와 WAL 관련 파일을 함께 보관하세요. 개인 DB·백업·초기 비밀번호·로그는 GitHub에 올리지 않습니다.

## HTTPS와 인증

현재 Tailscale Funnel 활성화와 연결을 완료했습니다.

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale funnel --bg 8787
```

공개 DNS의 Funnel 중계 경로로 HTTPS 상태 조회와 Pages CORS를 확인했습니다. 사용자가 두 휴대폰에서 같은 기록이 보이는 것도 확인했습니다. [Tailscale 공식 안내](https://tailscale.com/docs/features/tailscale-funnel)를 참조하세요.

로그인한 브라우저에 세션을 저장합니다. 사이트 데이터가 유지되는 같은 브라우저에서는 탭을 닫거나 브라우저를 종료한 뒤에도 로그인 상태가 유지됩니다. 서버 세션에는 시간제한이 없으며 로그아웃 시 서버 세션과 해당 브라우저의 로그인 정보를 해제합니다. 비밀번호와 세션 토큰은 서버에서 해시로 보관합니다.

CORS 허용 출처는 Pages와 지정된 로컬 주소이며, 별도 출처는 `--origin https://주소`로 추가합니다. 기록 API는 출처 허용과 별개로 로그인을 검사합니다. 서버는 지정한 프론트 파일만 제공하며 DB·소스·비밀번호 파일은 제공하지 않습니다.

[Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)로 보이지 않는 화면의 주기적 조회를 중지하고 복귀 시 다시 조회합니다. 실제 반영 시간에는 네트워크 상태와 휴대폰 브라우저의 백그라운드 제한이 영향을 줍니다.

## 검증과 다음 단계

### Antigravity CLI 연결

맥미니의 솜하우스 LaunchAgent를 실행하는 macOS 계정에서 Antigravity CLI를 설치하고 빈 작업 폴더에서 `agy`를 실행해 Google 로그인을 마칩니다. 연동은 macOS용 Antigravity CLI 1.5.6의 세션별 설정과 표준 입출력 기능을 사용합니다. Google은 개인 요금제에서 다른 앱이 `agy`를 백엔드로 호출하는 사용을 지원하지 않는다고 안내합니다. [설치와 인증](https://antigravity.google/docs/cli/install), [Google 공식 FAQ](https://antigravity.google/docs/faq)

먼저 개인정보가 없는 고정 질문으로 응답을 확인합니다. `agy` 설치 위치가 다르면 `--agy /절대경로/agy`를 붙입니다.

```sh
python3 server.py antigravity-test
```

응답이 확인되면 연결 설정을 저장하고 서비스를 재시작합니다. `antigravity-config`도 같은 연결 확인을 통과한 뒤에만 파일을 저장합니다.

```sh
python3 server.py antigravity-config
launchctl kickstart -k "gui/$(id -u)/com.ssoomm.somhouse"
```

서버는 질문을 CLI의 표준 입력으로 전달합니다. 기본 모델은 `gemini-3.8-flash-medium`입니다. 각 질문은 별도 CLI 프로세스에서 처리합니다. 질문은 Google로 전송되며, Antigravity 계정에 대화 기록이 남을 수 있습니다. AI 도구 권한은 잠그고, CLI 프로세스가 앱 소스와 가족 데이터 폴더를 읽거나 쓰는 작업은 macOS에서 차단합니다. 응답 제한은 20초입니다.

기본 설정은 질문만 전송합니다. 사용 중인 계정의 데이터 처리 조건이 허용할 경우, 관리자는 `python3 server.py antigravity-config --allow-record-summaries`로 가족 기록 집계를 활성화할 수 있습니다. 사용자가 질문마다 집계 하나를 선택하면 서버가 날짜와 숫자만 계산해 포함합니다. 원본 기록, 병원 정보, 메모, 제목과 링크는 집계에 포함되지 않습니다.

`GET /api/ai`는 연결 설정을, `POST /api/ai`는 답변을 반환합니다. 두 경로 모두 가족 로그인이 필요합니다. 기록 변경은 앱의 기존 기록 화면에서 수행합니다.

### 검증

```sh
node --test tests/*.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

JavaScript 검증은 자동 이전·원본 보존·추가/수정/삭제 자동 갱신·양식 유지·통신 실패·로그인 만료를 다룹니다. Python 검증은 임시 DB의 실제 HTTP API·인증·백업·관리자 복원·CORS와 실제 프론트 스크립트 두 세션의 자동 반영을 확인합니다. 이번 변경은 브라우저 제어 제한으로 실제 UI 자동 검증을 수행하지 못했습니다.

Antigravity 연동 테스트는 임시 데이터베이스와 모의 CLI 프로세스로 실행합니다.

서로 다른 기록은 항목별로 저장합니다. 같은 항목은 마지막 저장을 적용합니다. 동시 수정 충돌 처리 순서는 [SERVICE_PLAN.md](docs/SERVICE_PLAN.md)를 참조하세요.
