# 솜하우스

가족의 육아 기록, 일정, 구매 목록을 함께 관리하는 모바일 웹앱입니다. GitHub Pages의 같은 주소에서 가족 계정으로 로그인합니다. 추가·수정·삭제는 맥미니 SQLite에 저장하고, 다른 휴대폰에도 자동으로 반영합니다.

## 사용 흐름

- 로그인 후 모든 기록은 같은 가족 저장소를 사용합니다. 별도 공유·이전·새로고침 버튼은 없습니다.
- 사용자가 저장하거나 삭제하면 서버에 바로 반영합니다. 다른 휴대폰은 화면이 보일 때 2초 간격으로 변경을 확인합니다. 화면 복귀·네트워크 복구 때도 다시 조회합니다.
- 입력창·검색 조건을 작성 중이면 자동 화면 갱신을 보류해 입력을 유지합니다. 편집창을 닫으면 바로 다시 조회합니다. 변경이 없으면 목록을 다시 만들지 않습니다.
- 연결 실패 시 입력과 기존 목록을 유지하고 실패를 표시합니다. 저장되지 않은 내용을 저장 완료로 표시하지 않으며 기기 전용 저장으로 전환하지 않습니다.
- 로그인하지 않은 상태에서는 기록을 추가·수정·삭제할 수 없습니다.
- JSON 내보내기·가져오기, 기기 원본 백업·이전, 서버 주소 설정은 사용자 화면에 제공하지 않습니다. 백업·복원은 관리자가 맥에서 수행합니다.

홈의 빠른 기록·오늘 수유 요약, 육아 기록·일정·구매 목록의 검색과 필터를 제공합니다.

### 한 손 기록과 교대 요약

- **기저귀:** 홈의 ‘마지막 기저귀’ 칸에서 💧 소변 · 💩 대변 · 둘 다 중 하나를 누르면 지금 시각으로 바로 저장합니다. 기록 목록·기간 요약에도 횟수(소변·대변)가 나옵니다. 기저귀는 원본 시트·Tasks에는 남고 수유 캘린더에는 넣지 않습니다.
- **최근 수유 다시 기록:** 버튼을 누르면 입력창 없이 지금 시각으로 바로 저장합니다.
- **되돌리기:** 바로 저장한 뒤 8초 동안 아래 알림에 **되돌리기**(그 수유가 끝낸 수면도 다시 열기)와 **수정**이 나옵니다.
- **직수 타이머:** 마지막 수유 칸의 ‘왼쪽부터 / 오른쪽부터’ → 수유 중 ‘⇄ 반대쪽으로’ → **끝내기**. 시작 시각으로 `모유 N분`(메모에 좌·우 분)이 저장되고 열린 수면도 끝납니다. 타이머는 가족 휴대폰이 함께 보고 다른 휴대폰에서 끝낼 수 있습니다.
- **교대 요약:** 마지막 수유·수면·기저귀, 다음 수유 예상(최근 7일 평균 간격, 간격 3개 이상일 때), 24시간 안의 다음 일정, 가족이 남긴 **전달 메모** 한 줄, 마지막 업데이트 시각을 홈에 보여 줍니다.
- **최근 7일 하루 흐름:** 통계 화면 맨 위에 0~24시 막대(수면)와 점(수유·기저귀)으로 보여 주고, 누르면 그 기록을 엽니다. 자정을 넘긴 수면은 두 날에 나눠 그리고, 기간 요약의 수면 시간도 날짜별로 나눠 셉니다.
- **홈 화면에 설치:** 휴대폰 Chrome 메뉴 ⋮ → **앱 설치**(또는 홈 화면에 추가). 설치한 아이콘을 길게 누르면 ‘기저귀 소변’, ‘기저귀 대변’, ‘최근 수유 다시 기록’, ‘직수 타이머 시작’으로 바로 들어갑니다(바로 저장되고 되돌리기 알림이 나옴). 수유 용량은 단위가 명시된 기록만 합산합니다. 맥미니에 Codex·Claude·Antigravity CLI 중 하나 이상을 연결하면 로그인한 가족이 **AI 대화** 탭에서 골라 질문할 수 있습니다.

## 기존 기록 보존

기존 브라우저 localStorage의 `somhouse-v1` 원본은 읽기만 하며 덮어쓰거나 지우지 않습니다. 같은 사이트·브라우저에서 로그인하면 예전 기록을 자동으로 병합합니다. 같은 내용은 건너뛰고 ID가 같은 다른 내용은 별도 ID로 양쪽을 보존합니다. 이미 이전한 후 수정·삭제한 기록은 같은 원본을 다시 확인해도 되살리지 않습니다.

원본이 손상되었거나 브라우저 접근이 막혔으면 원본을 그대로 보존하고 안내합니다. 현재 가족 기록은 계속 사용할 수 있습니다. 이미 내려받은 JSON은 관리자 복원에 사용할 수 있습니다. 다른 사이트나 브라우저의 원본을 자동으로 읽을 수는 없습니다.

## 맥미니 실행

Python 3.10 이상이면 추가 패키지 없이 실행합니다.

```sh
python3 server.py init
python3 server.py serve
```

기본 전용 폴더는 `~/Library/Application Support/Somhouse/`이며 저장소 밖에 있습니다. `init`은 `family1`, `family2`와 임의의 초기 비밀번호를 생성합니다. 로그인 정보는 이 폴더의 `initial-accounts.txt`에만 저장합니다. 이미 계정이 있으면 계정이나 기록을 초기화하지 않습니다.

서버는 `http://127.0.0.1:8787/`에만 바인딩합니다. 휴대폰 프론트는 `config.js`의 HTTPS API 주소로 연결합니다. 이 파일에는 공개 주소만 두고 비밀번호·토큰·API 키는 넣지 않습니다.

```sh
python3 scripts/install_service.py
```

LaunchAgent `com.ssoomm.somhouse`는 맥 사용자 로그인 시 서버를 시작하고 종료되면 다시 실행합니다. 로그는 전용 폴더의 `service.log`, `service-error.log`에 저장합니다. 맥의 전원·사용자 로그인·네트워크가 유지되어야 합니다.

가족 계정으로 로그인한 뒤 상단의 **비밀번호 변경**에서 현재 비밀번호와 새 비밀번호를 입력하세요. 기억하기 쉬운 12~256자의 문구를 사용할 수 있습니다. 변경한 브라우저는 로그인 상태를 유지하고, 같은 계정의 다른 세션은 해제합니다.

현재 비밀번호를 잊었다면 관리자가 맥 터미널에서 재설정할 수 있습니다. 해당 계정의 모든 세션은 해제됩니다. 초기 로그인 정보 파일에는 처음 생성한 비밀번호만 남습니다.

```sh
python3 server.py password family1
```

### Google 로그인과 휴대폰에서 다시 연결

가족은 **솜하우스에 연결된 Google 계정과 같은 계정**으로만 Google 로그인할 수 있습니다(Google 고유 ID 비교). 이 로그인은 이름·이메일 권한만 쓰므로 Testing 앱의 7일 토큰 만료와 상관없이 유지됩니다. Google 연동에 "재연결 필요"가 뜨면 홈 맨 위의 **Google 다시 연결**(정상일 때는 맨 아래 연동 줄을 펼치면 있음)로 휴대폰에서 다시 승인합니다. 새 승인으로 기존 Tasks 목록·원본 시트·수유 캘린더를 실제로 읽어 본 뒤에만 바꾸고, 실패하면 이전 연결을 유지합니다. 처음 연결은 지금처럼 맥의 `scripts/connect_google_records.py`로 합니다.

관리자 설정(한 번):

1. Google Cloud Console → **Google Auth Platform → 클라이언트 → 클라이언트 만들기 → 웹 애플리케이션**
2. **승인된 JavaScript 원본**: `https://ssoommproject.github.io`
3. **승인된 리디렉션 URI**: `https://ssoomm-main.tail31d445.ts.net/api/google/callback`
4. 만든 클라이언트의 JSON을 맥에 내려받고 등록:

```sh
python3 server.py google-web-client --file ~/Downloads/client_secret_웹.json
```

`아이디로 로그인 (게스트·비상용)`의 비밀번호 로그인은 게스트와 비상용으로 남아 있습니다.

### 가족 구분 (같은 가족 = 같은 기록)

Google 로그인한 계정은 **한 가족**에 속하고, 그 가족의 기록만 봅니다. 가족끼리는 서로의 기록을 볼 수 없습니다.

- **연결된 가족 Google 계정**과 아이디 로그인(`family1`, `family2`)은 항상 처음부터 쓰던 가족(기본 가족)입니다. 기존 데이터 위치는 그대로입니다.
- **이메일 미리 등록:** 상단 **가족 관리 → 이메일로 미리 등록**에 Google 주소를 넣어 두면, 그 계정으로 로그인할 때 바로 같은 가족이 됩니다.
- **초대 링크:** **가족 관리 → 초대 링크 만들기 → 공유**. 링크를 열고 **Google로 로그인**하면 그 가족이 됩니다. 7일 동안 여러 명이 쓸 수 있고, 새 링크를 만들거나 **링크 끄기**를 누르면 이전 링크는 막힙니다.
- 등록·초대 없이 처음 로그인한 계정은 **빈 새 가족**으로 시작합니다(최대 20가족). 기록이 없는 새 가족에 혼자 있던 계정은 초대 링크로 다른 가족에 옮겨 갈 수 있습니다. 기록이 있거나 다른 구성원이 있는 가족에 속한 계정은 먼저 **나가기**를 해야 합니다.
- **내보내기/나가기:** 가족 관리에서 구성원을 내보내면 그 계정은 바로 로그아웃됩니다. 기록이 남은 가족의 마지막 구성원은 나갈 수 없습니다.
- 새 가족의 기록은 `families/<가족 ID>/somhouse.sqlite3`에 따로 저장되고 백업도 그 폴더에 남습니다. 없어진 빈 가족의 폴더는 지우지 않고 `families/.retired/`로 옮깁니다.
- **새 가족의 Google 연동:** **가족 관리 → Google 연결하기**를 누르고, 그 가족이 네스트·휴대폰에서 쓰는 Google 계정으로 모든 권한을 승인합니다. 그 계정에 `솜하우스 원본 기록` 시트, `솜하우스 웹 기록` Tasks 목록, 수유 캘린더를 만들고(실패해도 다시 연결하면 만든 것부터 이어서 진행), 그 계정의 음성 입력(Tasks 기본 목록·기본 캘린더)을 그 가족에만 가져옵니다. 캘린더 권한을 빼면 시트와 Tasks만 씁니다. 설정은 `families/<가족 ID>/google-records.json`에 저장되고, 맥 터미널 연결은 필요 없습니다.
- 한 Google 계정은 한 가족에만 연결할 수 있고, 기본 가족의 연결 계정은 다른 가족에 연결할 수 없습니다. Google 연결이 있는 가족은 자동으로 정리되지 않으며 마지막 구성원은 나갈 수 없습니다.
- Google 앱이 테스트 상태인 동안에는 각 가족도 7일마다 **Google 다시 연결**이 필요합니다(홈의 연동 줄이나 가족 관리의 **다시 연결**).
- 새 가족에는 AI 대화와 예전 기기 기록 가져오기가 없습니다. 공휴일은 모든 가족에 표시됩니다.
- Google 앱이 **테스트** 상태인 동안에는 Google Cloud Console → **Google Auth Platform → 대상 → 테스트 사용자**에 추가한 계정만 로그인할 수 있습니다(최대 100명).

관리자는 맥에서 가족 목록을 볼 수 있습니다.

```sh
python3 server.py families
```

### 게스트(읽기 전용) 계정

화면 구성과 사용법을 보여 줄 때 쓰는 계정입니다. 게스트는 실제 가족 기록 대신 서버가 오늘 날짜 기준으로 만든 **예시 기록**만 봅니다(공휴일은 실제 공개 목록). 입력창은 열어 볼 수 있지만 저장·수정·삭제·종류 확인·AI 질문·비밀번호 변경은 서버에서 모두 거절합니다. 같은 브라우저의 예전 기기 기록도 게스트 로그인으로는 서버에 보내지 않습니다.

```sh
python3 server.py guest
```

아이디 `guest`와 새 비밀번호를 출력합니다. 다시 실행하면 비밀번호가 바뀌고 기존 게스트 로그인은 모두 해제됩니다.

### 화면 미리보기 (로그인 없이 읽기)

다른 사람이나 LLM에게 UI를 보여 줄 때는 https://ssoommproject.github.io/somhouse/preview.html 링크를 주세요. 로그인 화면 뒤의 앱은 웹 읽기 도구가 열지 못하므로, 모든 화면과 입력창을 게스트 예시 데이터로 미리 그려 둔 정적 페이지입니다. 화면을 바꾼 뒤 `node scripts/build_preview.cjs`로 다시 만들고 함께 커밋합니다.

## 관리자 백업·복원

서버는 기록 변경 전에 전용 폴더의 `backups/`에 JSON을 자동 보관합니다. 백업 생성에 실패하면 기록을 변경하지 않습니다. 백업 파일은 웹으로 제공하지 않습니다. 새 자동 백업은 최근 100개와 최근 30일의 날짜별 마지막 1개를 보관합니다. 관리자 `backup` 명령의 백업과 기존 이름의 백업은 자동 정리하지 않습니다.

수동 백업:

```sh
python3 server.py backup
```

관리자 복원:

```sh
python3 server.py restore --file /안전한경로/backup.json
```

수면: 캘린더 제목에 `낮잠 40분`, `밤잠 2시간 30분`, `수면`, `잠`처럼 수면 말(수면·잠·낮잠·밤잠·꿀잠·잠듦·잤어·재웠어 등)을 적으면 수면 기록으로 저장합니다. 말은 낱말 단위로 비교하므로 `잠실`·`잠깐`은 수면이 아닙니다. 끝 시각은 제목의 길이, 없으면 캘린더 일정의 끝 시각을 쓰고, 입력한 시각으로 바꾼 일정이면 비워 둡니다. `수면`·`잠`만 있으면 07~19시는 낮잠, 그 외는 밤잠으로 추정하고 홈에서 확인받습니다. 수유 말·양이나 모르는 말이 섞이면 확인 필요로 남깁니다.

수면 시작·종료: 홈의 **😴 수면 시작**을 누르면 지금 시각으로 수면을 시작하고(07~19시 낮잠, 그 외 밤잠 — 나중에 수정 가능), **☀️ 수면 종료**를 누르면 깬 시각을 저장합니다. 수면 중에 웹·음성·캘린더로 수유가 기록되면 그 수유 시각을 깬 시각으로 저장해 수면을 끝냅니다. 수유보다 먼저 시작했고 16시간 안의, 깬 시각이 없는 가장 최근 수면 하나만 끝내며, 바뀐 수면은 Google에도 전송합니다. 수기 입력은 그대로 쓸 수 있습니다.

공휴일: 서버는 하루 한 번 Google의 공개 "대한민국의 휴일" 캘린더(ICS, 로그인 없음)를 받아 공휴일과 대체공휴일만 저장하고 가족 달력에 빨간 글씨로 표시합니다. 기념일(어버이날 등)은 표시하지 않습니다. 받기에 실패하면 마지막으로 받은 목록을 씁니다. 이 요청에는 가족 정보가 포함되지 않습니다.

관리자 기록 삭제 (시험 기록 정리 등):

```sh
python3 server.py delete-record --kind records --item-id <기록 ID>
```

삭제 전에 관리자 백업을 만들고 그 경로를 출력합니다. Google로 보낸 적이 있는 기록이면 Tasks 사본·원본 시트·수유 캘린더에도 삭제가 반영되고, 보낸 적이 없는 기록이면 외부에 흔적을 남기지 않습니다. 웹의 삭제 버튼은 항상 Google에 삭제 이력을 남깁니다.

복원은 파일 전체를 검증하고 현재 상태를 먼저 백업한 뒤 병합합니다. 현재 기록은 삭제하지 않으며 같은 내용은 건너뜁니다. 삭제했던 기록을 복구할 수 있고, 현재와 다른 버전은 별도 기록으로 남을 수 있습니다. 가족 계정으로 호출하는 웹 복원 API는 제공하지 않습니다. 복원 작업은 다른 기록 변경이 없는 점검 시간에 수행하세요.

`somhouse.sqlite3`는 계정과 세션도 포함합니다. DB 전체 백업은 SQLite 백업 API를 사용하거나 서버를 종료하고 DB와 WAL 관련 파일을 함께 보관하세요. 개인 DB·백업·초기 비밀번호·로그는 GitHub에 올리지 않습니다.

## HTTPS와 인증

현재 Tailscale Funnel 활성화와 연결을 완료했습니다.

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale funnel --bg 8787
```

공개 DNS의 Funnel 중계 경로로 HTTPS 상태 조회와 Pages CORS를 확인했습니다. 사용자가 두 휴대폰에서 같은 기록이 보이는 것도 확인했습니다. [Tailscale 공식 안내](https://tailscale.com/docs/features/tailscale-funnel)를 참조하세요.

로그인한 브라우저에 세션을 저장합니다. 사이트 데이터가 유지되는 같은 브라우저에서는 탭을 닫거나 브라우저를 종료한 뒤에도 로그인 상태가 유지됩니다. 서버 세션에는 시간제한이 없으며 로그아웃 시 서버 세션과 해당 브라우저의 로그인 정보를 해제합니다. 비밀번호와 세션 토큰은 서버에서 해시로 보관합니다.

CORS 허용 출처는 Pages와 지정된 로컬 주소이며, 별도 출처는 `--origin https://주소`로 추가합니다. 기록 API는 출처 허용과 별개로 로그인을 검사합니다. 서버는 지정한 프론트 파일만 제공하며 DB·소스·비밀번호 파일은 제공하지 않습니다.

[Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)로 보이지 않는 화면의 주기적 조회를 중지하고 복귀 시 다시 조회합니다. 실제 반영 시간에는 네트워크 상태와 휴대폰 브라우저의 백그라운드 제한이 영향을 줍니다.

## 검증과 다음 단계

### 네스트 허브·Google Tasks·원본 시트 연결

웹은 SQLite에서 정리한 기록으로 검색과 요약을 보여 줍니다. 설정을 켜면 웹에서 새로 저장하거나 수정한 수유·병원·일정·구매 기록이 Google Tasks의 **솜하우스 웹 기록** 목록과 Google Sheets의 **솜하우스 원본 기록**에도 반영됩니다. Google 장애 시에도 가족 웹은 SQLite에 저장하고 대상별로 전송을 재시도합니다. 웹 삭제는 원본 시트에 삭제 이력을 남기고 해당 웹 복사본을 Tasks에서 삭제 표시 후 완료 처리합니다.

네스트에서 만든 할 일은 Google Tasks의 음성 입력 목록(기본값은 기본 할 일 목록)으로 들어옵니다. 약 30초마다 제목이 **솜하우스**로 시작하거나 아래 장보기 형식에 맞는 할 일을 가져옵니다. 정상 해석된 기록은 SQLite에 추가되고, 인식된 제목과 원본 Task 데이터는 시트에 기록됩니다. 해석하기 어려운 문구는 시트에 **확인 필요**로 표시되고 웹 집계에는 포함되지 않습니다. 확인이 필요한 할 일의 제목을 수정하면 다시 해석합니다. 등록된 음성 기록을 웹에서 수정해도 원래 음성 Task의 제목은 보존됩니다. 최초 연결 시 지정한 목록의 기존 제목도 검사합니다.

Google Home에서 네스트의 Voice Match와 개인 검색 결과를 켜고, 음성 입력에 쓰는 Google 계정을 확인하세요. **“헤이 구글, 할 일 만들어 줘”**라고 말하고 제목을 물으면 아래처럼 말해 보세요. 실기기의 한국어 인식 결과는 먼저 휴대폰 Tasks에서 확인해야 합니다. [Google Home의 할 일 안내](https://support.google.com/googlehome/answer/16722329?hl=ko)

| Tasks에 남아야 할 제목 예시 | 저장되는 기록 |
| --- | --- |
| 솜하우스 수유 분유 120 밀리리터 | 분유 120ml |
| 솜하우스 수유 모유 15 분 | 모유 15분 |
| 솜하우스 병원 솜소아과 이유 예방접종 | 병원 방문 |
| 솜하우스 일정 2026년 11월 20일 오후 2시 예방접종 | 지정 일시의 일정 |
| 솜하우스 구매 물티슈 수량 2개 | 구매 항목 |

수유와 병원 기록에는 처음 가져왔을 때의 Tasks 수정 시각을 서울 시각으로 저장합니다. Google이 시각을 제공하지 않으면 최초 수집 시각을 사용합니다. 확인이 필요한 제목을 나중에 고쳐도 이 기준 시각을 유지합니다. 수유는 `솜하우스 수유 분유 120cc 오후 3시`처럼 말한 시각도 받을 수 있습니다. `ml`, `밀리리터`, `미리`, `cc`, `씨씨`는 같은 용량 단위로 처리합니다. 실제 수유나 방문 시각과 다르면 웹에서 수정하세요. 일정은 제목에 날짜와 시간이 모두 있어야 합니다. Tasks API의 예정 날짜는 시각을 제공하지 않습니다. [Tasks 필드 명세](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks)

관리자 연결은 다음 순서로 합니다.

1. Google Cloud Console에서 프로젝트를 선택하고 **Google Tasks API**, **Google Sheets API**, **Google Calendar API**를 사용 설정합니다. [Tasks API 설정](https://developers.google.com/workspace/tasks/quickstart/python#set_up_your_environment) · [Sheets API 설정](https://developers.google.com/workspace/sheets/api/quickstart/python#set_up_your_environment) · [Calendar API 설정](https://developers.google.com/workspace/calendar/api/quickstart/python#set_up_your_environment)
2. **Google Auth Platform → 잠재고객(Audience)**에서 개인 Gmail은 **외부(External)**를 선택하고, 테스트 사용자에 네스트와 같은 계정을 등록합니다. **클라이언트(Clients) → 클라이언트 만들기 → 데스크톱 앱**을 선택해 JSON을 맥에 다운로드합니다. [동의 화면](https://developers.google.com/workspace/guides/configure-oauth-consent) · [데스크톱 OAuth 사용자 인증 정보](https://developers.google.com/workspace/guides/create-credentials#desktop-app)
3. 아래 명령을 실행하고 브라우저에서 네스트와 같은 계정으로 직접 로그인해 권한을 승인합니다. 솜하우스는 별도의 웹 기록 Tasks 목록과 원본 시트를 만들고, OAuth 갱신 토큰을 권한이 제한된 맥미니 데이터 폴더에 저장합니다. 같은 Google 계정으로 재연결하면 기존 목록, 시트, 대기 작업을 유지합니다.

```sh
python3 -m venv .local-data/google-venv
.local-data/google-venv/bin/python -m pip install google-auth-oauthlib==1.4.1
.local-data/google-venv/bin/python scripts/connect_google_records.py --client "$HOME/Downloads/google-oauth-client.json" --calendar
launchctl kickstart -k "gui/$(id -u)/com.ssoomm.somhouse"
python3 server.py google-status
```

명령의 JSON 경로는 실제 다운로드한 파일 이름으로 바꿉니다. 음성이 기본 목록이 아닌 다른 목록으로 들어가면 연결 스크립트의 `--list-inboxes`로 목록 ID를 확인한 뒤 `--inbox 목록_ID`를 붙여 다시 연결하세요. OAuth 앱이 **테스트 중**이면 Google이 갱신 토큰을 7일 뒤 만료시킵니다. [Google 토큰 만료 안내](https://developers.google.com/identity/protocols/oauth2#expiration)

가족 웹에 로그인하면 **원본 시트**와 **Google Tasks** 링크, 대상별 미전송·재시도·실패 건수와 마지막 전송 시각이 표시됩니다. OAuth 갱신이 `invalid_grant`로 거절되면 **재연결 필요**를 표시하고 Google 요청을 중지합니다. 같은 설정으로 재시작해도 중지를 유지하며, 연결 명령으로 새 토큰을 받은 뒤 서버를 재시작해야 합니다. 가족과 원본을 공유하려면 담당자가 원본 시트를 해당 가족 Google 계정에 **뷰어**로 공유합니다. Tasks는 연결 계정의 목록입니다. 원본 탭에는 편집 경고 보호를 설정합니다. 행 충돌이나 응답 유실 후에는 이벤트 ID로 기존 행을 확인하고, 없는 이벤트만 원격 마지막 행과 로컬 예약 행 뒤에 배정합니다. 편집 경고는 동시 수정을 차단하지 않으므로 직접 정렬보다는 별도 복사본이나 필터 보기를 사용하세요. 병원 방문 사유와 메모도 원본에 포함됩니다.

활성화 전에는 기존 웹 기록을 일괄 복사하지 않습니다. 기존 기록은 웹에서 다시 저장하거나 관리자가 `python3 server.py google-backfill`을 실행할 때 복사됩니다. backfill은 항목 ID와 내용 해시로 같은 내용을 반복 예약하지 않습니다. 각 전송은 30초부터 지수 백오프로 재시도하며, 5회 실패하면 격리하고 다음 기록을 계속 전송합니다. 원인 해결 후 `python3 server.py google-retry`로 실패·재시도 항목을 다시 대기열에 넣을 수 있습니다. 이 명령은 인증 만료를 해제하지 않습니다. `google-status`로 대상별 전송 대기와 음성 확인 필요 건수를 보고, `service-error.log`에서 동기화 오류를 확인할 수 있습니다. 연결을 끄려면 전용 데이터 폴더의 `google-records.json`을 비공개 위치로 옮기고 서버를 재시작하세요.

### Calendar로 수유 기록 확인

연결할 때 `--calendar`를 붙이면 **기본 캘린더를 읽을 권한**과 앱이 만드는 별도 캘린더 **솜하우스 수유**를 관리할 권한을 요청합니다. Tasks·Sheets가 이미 연결돼 있어도 같은 계정으로 이 명령을 다시 실행해 권한을 추가할 수 있습니다. [Google Calendar 권한 범위](https://developers.google.com/workspace/calendar/api/auth)

- 네스트에 **“헤이 구글, 내 캘린더에 일정 추가해 줘”**라고 요청하고, 이름을 물으면 **“솜하우스 수유 분유 120 밀리리터”**라고 말하세요. 날짜와 시작 시간은 실제 수유 시각을 답합니다. **“헤이 구글, 100미리 수유 캘린더에 업데이트”**처럼 `솜하우스` 없이 말해도, 일정 제목에 `수유`·`분유`·`모유`와 단위 있는 양(ml·미리·cc, 직수는 분)만 있으면 수유로 저장합니다. 종류(분유·모유·혼합)를 말하지 않았거나 `수육`·`부유`·`머유`처럼 비슷하게 들린 말이면 일단 `기타`로 저장하고 **종류 확인 필요**로 표시합니다. 웹 홈의 **수유 종류를 골라 주세요** 상자에서 한 번 눌러 확정합니다. `부유`를 분유로 확정하면 그 말을 기억해 다음부터 자동으로 분유로 저장하고, 잘못 골랐다면 그 기록을 **수정**해 종류를 바꾸면 기억한 말도 함께 바뀝니다(`기타`로 바꿀 때는 기억을 그대로 둡니다). 기억한 말은 홈의 음성·캘린더 안내에서 **잊기**로 지울 수 있습니다. `수`로 시작하는 말은 `수유`가 잘못 들린 것으로 보고 기억하지 않습니다. 자주 생기는 오인식(`수육`→`수유`, `100mm`→`100ml`, 끼어든 숫자 하나)은 고쳐서 저장하고 메모에 음성 원문을 남깁니다. 모르는 단어가 섞였거나 양·종류가 둘 이상인 제목은 저장하지 않고 **확인 필요**로 남기며, 웹 홈의 **확인 필요** 목록에서 바로 정정할 수 있습니다. 단위 있는 양이 없는 일반 일정(예: `수육 맛집`, `분유 사기 2통`)은 가져오지 않습니다. 다만 `수유`·`분유`나 기억한 말(`뷰유`)처럼 수유 말만 적힌 일정은 양을 입력할 수 있도록 **확인 필요**로 남깁니다. 같은 Google 계정이면 휴대폰·태블릿의 음성 입력이나 Google 캘린더 앱에 직접 적은 일정도 똑같이 처리합니다. 직접 적은 일정은 시작 시각이 만든 때부터 2시간 안의 미래이거나 만든 날의 종일 일정이면 **만든 시각**으로 저장하고 메모에 그 사실을 남깁니다. 시작 시각이 과거면 그 시각을 실제 수유 시각으로 씁니다. 그 일정의 제목과 시작 시간이 SQLite 수유 기록과 Sheets 원본 이력에 들어갑니다. 여러 번 조회해도 같은 일정 ID는 같은 수유 기록입니다. 다른 날짜의 종일 일정이거나 양을 알 수 없는 일회성 수유 일정, 만든 때부터 2시간보다 먼 미래 시각의 수유 일정은 시트에 **확인 필요**로 남기며 수유 집계에 넣지 않습니다. 미래 일정은 시간이 지나도 자동으로 실제 수유가 되지 않으며 제목·시각을 확인해 수정해야 합니다. [네스트에서 일정 추가](https://support.google.com/googlehome/answer/7029002?hl=ko)
- 웹이나 Tasks에서 새로 저장한 수유는 **솜하우스 수유** 캘린더에 복사됩니다. 앱에서 만든 복사본은 웹 수정·삭제에 맞춰 갱신됩니다. 네스트가 기본 캘린더에 만든 일정은 그곳에서 그대로 볼 수 있습니다. 기본 캘린더의 수유 일정을 고치면 그 기록을 갱신합니다. 웹에서도 고친 기록이면 항목별로 합칩니다. 예를 들어 웹에서 종류를 고르고 캘린더에서 시각이나 양을 고치면 둘 다 반영하고, 같은 항목을 서로 다르게 고친 경우에만 웹 값을 유지한 채 확인 필요로 남깁니다. 같은 일정을 고치는 것은 새 수유가 아니라 같은 기록의 수정입니다. `솜하우스` 태그를 제거하거나 일정을 삭제하면 웹에서 수정하지 않은 자동 수집 기록을 철회합니다. 웹 수정본은 보존하고 확인 필요 건수에 포함합니다. 처음에는 지난 7일부터의 일정을 확인합니다.
- 휴대폰 Google Calendar 앱의 **☰ 메뉴**에서 **기본 캘린더**와 **솜하우스 수유**를 모두 표시하세요. Android 홈 화면의 **Calendar 월간 보기** 위젯에서 지나간 날짜의 기록도 확인할 수 있습니다. **캘린더 일정** 위젯은 예정된 항목 중심입니다. [Android Calendar 위젯](https://support.google.com/calendar/answer/10249848?co=GENIE.Platform%3DAndroid&hl=ko) · [iPhone Calendar 위젯](https://support.google.com/calendar/answer/10249848?co=GENIE.Platform%3DiOS&hl=ko)

### 음성 장보기와 가격 링크

네스트에서 할 일을 만들고 제목으로 **“기저귀 구매”**라고 말하세요. Tasks에 **기저기 구매**라고 저장돼도 웹 구매 목록에는 **기저귀**로 정리합니다. 태그 없이 **구매** 또는 **구입** 표현으로 끝난 미완료 할 일은 관리자가 등록한 상품 별칭과 일치할 때만 가져옵니다. 등록되지 않은 상품은 **솜하우스 구매 …**로 명시해야 합니다. `보험 구매`, `선물 구입하기` 같은 태그 없는 개인 할 일은 가져오지 않습니다. 원래 Task 제목과 기존 메모는 보존하고, 같은 Task의 메모에 **가격비교** 링크를 덧붙입니다.

상품, 단계, 포장 매수를 지정하면 설정한 SerpApi에서 검색해 규격과 일치하는 원화 상품 결과 중 가장 낮은 표시가와 링크를 넣습니다. 결과에는 조회 시각이 남습니다. 배송비·쿠폰·옵션은 표시가 비교에 포함되지 않으며, 조건이 모호하면 쇼핑 검색 링크와 상태를 남깁니다. 검색 연결 실패는 백오프로 재시도하고 반복 실패를 연동 상태에 표시합니다. 체중 범위와 `1팩` 표기는 허용하지만 다른 단계·매수와 추가 묶음 상품은 제외합니다. 숫자 가격은 `extracted_price`를 우선 쓰되 원화 표시도 확인합니다. 네이버의 기존 쇼핑 검색 API는 종료됐습니다. [SerpApi 상품 검색 명세](https://serpapi.com/shopping-results) · [네이버 종료 공지](https://developers.naver.com/notice/article/32564)

**“기저귀 구매”**만으로 평소 상품을 찾으려면 아래 예시의 상품명을 실제 사용하는 제품으로 바꾸고 별칭을 등록하세요. SerpApi 키는 숨김 입력으로 등록하며, 검색에는 상품 검색어만 사용합니다. 서버를 재시작하면 새 장보기 Task에 적용됩니다.

```sh
python3 scripts/configure_shopping.py --set-key
python3 scripts/configure_shopping.py --alias 기저귀 --product '예시브랜드 기저귀 4단계 40매'
launchctl kickstart -k "gui/$(id -u)/com.ssoomm.somhouse"
```

### AI 연결 (Codex · Claude · Antigravity)

AI 대화 탭은 세 AI를 접힌 카드로 보여 주고, 연결한 AI만 펼쳐서 고를 수 있게 합니다. 연결 방법은 두 가지입니다. 마지막으로 고른 AI는 기기에 기억됩니다.

- **맥미니 CLI (처음 만든 가족만):** 관리자가 맥미니에 한 번 연결하면 가족은 키 없이 씁니다. 답변은 관리자의 구독 계정으로 나갑니다. 아래 절차를 따릅니다.
- **내 API 키 (모든 가족):** 카드를 펼쳐 OpenAI·Anthropic·Gemini API 키를 붙여 넣고 **연결**을 누릅니다. 키는 그 기기의 브라우저에 로그인한 계정별로 저장되고, 솜하우스 서버로는 보내지 않습니다. 질문은 기기에서 AI 회사로 바로 가고(`ai-direct.js`), 요금은 키 주인에게 청구됩니다. 연결할 때는 모델 목록만 불러와 키를 확인하므로 토큰을 쓰지 않습니다. 모델은 카드에서 바꿀 수 있습니다(기본: Claude `claude-opus-5-5`, OpenAI·Gemini는 계정에서 쓸 수 있는 최신 모델). 가족 기록 집계는 기기에서 맥미니와 같은 방식(날짜와 숫자만)으로 계산해 보냅니다. 키를 지우려면 카드의 **키 연결 해제**를 누르고, 키 자체는 AI 회사 사이트에서 삭제합니다. 공용 기기에서는 연결하지 마세요.

다른 가족에게는 맥미니 연결 안내가 보이지 않습니다.

이하는 맥미니 CLI 연결 절차입니다.

| AI | 회사 | CLI 로그인 (LaunchAgent와 같은 macOS 계정, 빈 폴더에서) | 기본 위치 | 기본 모델 |
| --- | --- | --- | --- | --- |
| Codex | OpenAI | `codex login` | `~/.local/bin/codex` | CLI 기본값 (추론 강도 low) |
| Claude | Anthropic | `claude` 실행 후 `/login` | `/opt/homebrew/bin/claude` | `sonnet` |
| Antigravity | Google | `agy` | `~/.local/bin/agy` | `gemini-3.8-flash-medium` |

각 회사의 개인 요금제 약관이 다른 앱이 CLI를 백엔드로 호출하는 사용을 허용하는지 확인하세요. Google은 Antigravity에서 이런 사용을 지원하지 않는다고 안내합니다. [Antigravity FAQ](https://antigravity.google/docs/faq)

연결은 개인정보가 없는 고정 질문으로 응답을 확인한 뒤에만 저장됩니다. 하나를 연결해도 다른 AI 설정은 그대로입니다. 저장 후 서비스를 재시작합니다.

```sh
python3 server.py ai-config --provider codex      # 또는 claude, antigravity
python3 server.py ai-status                       # 연결 상태 보기
launchctl kickstart -k "gui/$(id -u)/com.ssoomm.somhouse"
```

설치 위치가 다르면 `--bin /절대경로`, 모델을 바꾸려면 `--model 이름`을 붙입니다. 저장하지 않고 응답만 보려면 `ai-test`, 연결을 끊으려면 `ai-disconnect --provider codex`(재시작 필요)를 씁니다. 예전 `antigravity-config`·`antigravity-test` 명령과 `antigravity-config.json` 파일도 그대로 동작합니다.

서버는 질문마다 빈 임시 폴더에서 CLI 프로세스를 하나 실행하고 질문을 표준 입력으로 전달합니다(명령줄 인수에는 질문이 들어가지 않습니다). 셸·파일·웹 검색·MCP·플러그인 같은 도구는 모두 끄고, 사용자 설정·지침 파일(`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, 스킬, 메모리 등)도 읽지 않게 합니다. 앱 소스와 가족 데이터 폴더를 읽거나 쓰는 작업은 macOS 샌드박스가 차단합니다. API 키 환경 변수는 전달하지 않습니다. 질문은 고른 AI의 회사로 전송되며 그 계정에 사용 기록이 남을 수 있습니다. 응답 제한은 45초이고, 한 사람당 동시에 1개·1분에 6개까지 질문할 수 있습니다(세 AI 합산). 답변을 받지 못하면 서버가 AI 이름, 종료 코드와 CLI 오류 요약을 `service-error.log`에 남기며, 질문 내용은 기록하지 않습니다. 로그인 만료, 사용 한도, 모델 사용 불가는 각각 따로 안내합니다.

기본 설정은 질문만 전송합니다. 사용 중인 계정의 데이터 처리 조건이 허용할 경우, 관리자는 AI별로 `--allow-record-summaries`를 붙여 연결하면 가족 기록 집계를 활성화할 수 있습니다. 사용자가 질문마다 집계 하나를 선택하면 서버가 날짜와 숫자만 계산해 포함합니다. 원본 기록, 병원 정보, 메모, 제목과 링크는 집계에 포함되지 않습니다.

`GET /api/ai`는 맥미니 AI별 연결 상태(`providers`, 다른 가족에게는 모두 연결 안 됨)를, `POST /api/ai`(`question`, `scope`, `provider`)는 답변을 반환합니다. 두 경로 모두 가족 로그인이 필요합니다. 기록 변경은 앱의 기존 기록 화면에서 수행합니다.

### 개인 ChatGPT 구독으로 질문하기

연결을 설정한 서버에서는 **AI → 내 ChatGPT 구독 → ChatGPT로 계속하기**를 누릅니다. 본인의 ChatGPT 계정을 선택하고 플랜 사용에 동의한 뒤 솜하우스에서 질문합니다. 처음에는 계정에 표시되는 첫 모델을 사용합니다. **ChatGPT 모델**에서 다른 모델을 골라 질문하면 다음 방문에도 마지막으로 질문에 사용한 모델이 선택됩니다. 사용 가능한 모델이 바뀌면 **모델 목록 새로고침**을 누르세요. 이번 버전은 입력한 질문만 전송합니다. 사용 한도나 권한 오류는 그 자리에서 안내합니다. 사용량은 ChatGPT에서 관리하며 별도 결제 수단으로 자동 재시도하지 않습니다.

연결은 현재 기기의 솜하우스 로그인 세션에 귀속됩니다. 가족이 같은 솜하우스 아이디로 다른 기기에 로그인해도 각자 연결해야 합니다. 토큰은 서버의 가족별 비공개 SQLite에 저장합니다. 가족 기록 JSON 백업과 브라우저 저장소에는 포함하지 않습니다. 로그아웃하거나 구독 연결을 해제하면 로컬 인증 정보가 삭제됩니다. OpenAI 측 권한은 ChatGPT 설정에서도 해제할 수 있습니다.

**개인 Mac에서 먼저 시험할 때**는 프로젝트 폴더에서 아래 명령을 실행하고 같은 Mac의 브라우저에서 [시험판](http://127.0.0.1:18764/#ai)을 엽니다. 실행한 터미널에 표시되는 초기 계정 파일의 아이디·비밀번호를 사용합니다. 시험판에는 별도 데이터 폴더와 포트를 사용합니다. OpenAI는 로그인 후 이 컴퓨터의 `/auth/callback`으로 돌아옵니다.

```sh
python3 -m venv /tmp/somhouse-chatgpt-venv
/tmp/somhouse-chatgpt-venv/bin/pip install -r requirements-chatgpt.txt
/tmp/somhouse-chatgpt-venv/bin/python server.py init --data-dir /tmp/somhouse-chatgpt-local
/tmp/somhouse-chatgpt-venv/bin/python server.py serve --chatgpt-local --port 18764 --data-dir /tmp/somhouse-chatgpt-local
```

**휴대폰에서 접속하는 운영 웹**에는 OpenAI가 호스팅 앱의 **ChatGPT plan usage**를 승인하고 발급한 클라이언트 ID가 필요합니다. 신청할 콜백은 서버 공개 HTTPS 주소 뒤에 `/auth/openai/callback`을 붙인 값입니다. 승인 안내의 사용 권한·토큰 인증 방식·추론 계약을 확인한 후, 서비스를 실행하는 Python에 위 의존성을 설치하고 운영 데이터 폴더의 `chatgpt-web-client.json`에 아래 값을 저장합니다(소유자만 읽기·쓰기, 0600). `none` 인증이면 비밀값을 생략하고, `client_secret_basic`이면 `client_secret`에 발급받은 값을 추가합니다. 서비스 재시작 후 테스트 계정 하나에서 동의, 질문, 연결 해제를 검증합니다. 설정 파일이 없으면 AI 탭의 **내 ChatGPT 구독**에 **서버 설정 필요**가 표시됩니다. 이때 **ChatGPT 웹에서 직접 질문하기**를 누르면 ChatGPT가 새 탭에서 열립니다.
